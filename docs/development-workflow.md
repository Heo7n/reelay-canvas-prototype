# Reelay Vibe coding 开发规范

本文件是设计、实现、协作、清理与交付的统一工作流。产品行为、视觉参数和工程不变量分别由对应规范维护，不在每轮任务另建一份规则。

## 1. 开始：核对事实与本次范围

```powershell
git status --short --branch
npm run worktrees
```

先确认实际目录、分支、脏文件和运行服务，再读[当前交接](agent-handoff.md)。根据下表读取相关章节，不默认通读所有长文档；发现文档与运行证据冲突时先核实根因并修正文档。

用简短说明明确本次的**触发动作、预期反馈、应保留状态、完成标准**。可逆的实现细节可注明假设后推进；只有缺失的产品规则、数据范围或必要授权阻挡实施时才集中澄清。用户方案是输入，需独立判断，不为了迎合而照搬草图或其它产品。

## 2. 设计与实现

### 从完整行为切片开始

- 先明确内容、草稿、任务、UI 状态分别由谁拥有，生命周期何时开始 / 结束，再确定视觉与模块边界。
- 修复根因：用正确不变量或状态转移替换错误路径，不追加补偿 timer、render 清洗、重复状态或特殊例外来遮盖问题。
- 选择能独立验收的最小完整改动；不顺带重写无关模块，不让新旧状态路径长期同时活跃。
- 优先复用实际存在的 token、组件、controller 和服务。重复“长得像”不等于应抽象；当职责和生命周期一致时再抽取。
- 每个提交表达一个可回退意图。功能、迁移和无关清理分开；不把全仓格式化混入行为修复。

### 目录与代码约定

- 新产品页面进入 React 路由壳，不向 `app.js` 增加页面、账户或 repository 逻辑。它只保留现有画布组装与适配，新完整交互放进对应功能模块。
- domain 不依赖 UI / HTTP / 数据库；application 定义用例和 ports；adapters 实现 I/O。Host / bridge 只承载明确的上下文、导航和迁移通信。
- 按数据所有权和可独立验收的职责拆分，不按行数机械拆文件。模块只接收所需读取、提交、通知能力，不把整个全局 `state` 传进去。
- 模型 ID、能力、参数、模拟成本和默认优化规则在 `data/model-catalog.js` 维护，页面通过目录读取。
- 节点生成的注册、timer、取消和完成由 `canvas-node-task-runner.js` 管理；对话生成与非写入的提示词优化分别使用自己的 service。优化完成不改 Prompt，手动应用经 adapter 提交一次可撤销写入。
- 内容字段、组关系、作用域和撤销复用现有事务契约；异步完成校验实际 owner，清理订阅 / timer / observer，旧回调不能串项目、画布或草稿。详细不变量只在工程护栏维护。
- 新增 TS 使用严格类型，边界输入先校验；不以 `any`、`@ts-ignore` 或全局关闭检查掩盖问题。legacy 局部修改沿用现有风格，保持两空格、LF 和就近命名习惯，不为统一语言整片改写。
- 引入依赖要有具体用途并提交锁文件；图标优先复用现有 Lucide。注释解释原因、约束和副作用，过期注释随实现一起移除，不保留大段被注释掉的旧实现。

## 3. 迭代与验收

### 按影响选择检查

局部迭代先运行实际受影响的测试文件；`check:canvas` / `check:legacy` 都是广域检查，不能当成单个按钮的最小检查。

| 范围 | 迭代入口 |
| --- | --- |
| JS / TS 代码规则 | `npm run lint -- src/<本次文件>`；全仓 `npm run lint` |
| legacy 纯视觉微调 | `npm run check:visual`（CSS / HTML 静态检查）+ 当前预览查看实际效果 |
| legacy 某个行为 | `node --test tests/<相关文件>.test.mjs` |
| CSS / HTML / JS 语法 | 对应 `npm run check:css` / `check:html` / `check:js` |
| React / TS 页面或领域 | 对应 Vitest 文件；阶段检查 `npm run check:shell` |
| API / service / adapter | 对应 Vitest 文件；阶段检查 `npm run check:server` |
| PostgreSQL schema / migration / adapter | 上项 + 独立本机数据库的 `npm run check:server:postgres` |
| 构建 / 入口 / 路由 | `npm run build`；影响体验分支时加 `npm run build:experience` |
| 文档 | `npm run check:docs` 与 `git diff --check` |

视觉微调不运行全量测试或重复构建，也不为每次间距调整单独提交。React CSS 以 Vite 编译和实际页面为准，`check:visual` 不代替其构建校验。行为变化先跑对应文件，阶段收口再执行下述完整检查；“1687 项测试”是许多快速断言，不是 1687 次浏览器操作。

代码里程碑或提交前统一执行：

```powershell
npm run check
git diff --check
```

`check` 不依赖 Docker；数据库切片仍必须跑 PostgreSQL 集成验证，内存 adapter 不能替代。仅文档的里程碑按文档检查，不要求全画布回归。

`lint` 已进入本地 `check` 与 CI，覆盖源码、脚本和测试的基础正确性规则，TS 禁止显式 `any` 和无理由跳过类型检查。缓存不入 Git，单文件检查用于日常迭代。暂不引入格式化或对 legacy 全量删未使用声明；TS 未使用声明仍由现有编译器检查。控制字符校验正则、Playwright fixture 空解构与源码片段测试采用有说明的规则配置，不为了通过 lint 改弱数据校验。

核心依赖边界已自动拦截：`domain` 只依赖内部领域代码；`application` 与 `server/application` 可依赖领域和对应 ports，不得反向导入页面、HTTP / 数据库实现。当前仅放行纯校验库 `zod`；静态导入、再导出、动态导入、`require` 和 TS 类型导入统一检查，非字面量动态路径拒绝。测试文件可以导入测试框架及适配器。该规则检查模块导入，不宣称已约束 legacy 经 `window.REELAY_*` 传递的所有运行时依赖，也不替代权限、数据或状态测试。

`npm test` 自动发现 `tests/*.test.mjs` 并执行 legacy 打包测试；`test:canvas` 是兼容别名，不再维护另一份清单。shell / server 测试按各自 Vitest 配置发现，启动 / 初始化脚本测试保留专用入口。新增测试必须实际进入对应命令。

### 关键浏览器验收

首次安装依赖后执行 `npx playwright install chromium`（CI 使用 `--with-deps`）；之后运行 `npm run test:e2e`，构建账号产物并自动启动 / 关闭使用系统空闲端口的隔离内存服务。已构建同一代码时用 `npm run test:e2e:run`；只验一个流程可追加 `-- tests/e2e/<文件>.spec.ts`。不用手工启动测试服务；端口由操作系统一次性分配，测试浏览器只访问该实例，不复用 5174 / 5175 或其它运行中的服务。

当前覆盖登录后编辑画布、返回重进与刷新读回；生成成功自动放置及定位；取消与退款；优化建议手动填入、引用保留及撤销。使用真实浏览器操作和 HTTP，服务端全部显式注入内存 stores，不读取环境文件、不连接数据库或云端素材。外部模拟结果媒体由测试替换为仓库样本，其它外网请求直接拒绝。它验证浏览器与 API 的链路，不能替代 PostgreSQL 重启持久化或真实供应商验收。

`npm run check` 只包含这些脚本的类型检查，不启动浏览器。CI 单独执行浏览器任务；本地仅在相关核心流程改动和阶段验收时运行，不加入每次视觉反馈循环。失败保留 trace 与截图到忽略目录 `test-results/`，不以重试掩盖不稳定结果。

### 验证什么

- 测试验证可观察行为、状态归属和失败边界。避免只断言变量名、源码片段或精确 CSS 写法；必要的入口 / 协议静态契约保留。
- UI 改动检查受影响页面、容器最小 / 最大宽度、浅深主题、键盘与控制台；先做本轮视觉收口，再生成发布候选。
- 画布手势检查相应选择、拖动、连线、缩放与撤销。只调隔离画布可使用 `dev:canvas`，项目权限 / 保存验证必须走完整路由。
- 生成、资产、保存或异步归属变化检查跨画布 / 跨项目不串写；积分变化检查当前 `3000 / 0` 刷新契约。持久账本接入后改为余额一致性及扣费 / 退款幂等验证。
- 可逆文案 / 间距微调通常不增加镜像实现的测试。已有同代码状态的检查不为写 PR 或等 CI 反复重跑；新修改、失败或风险证据才触发补验。
- 性能结论需记录环境和测量口径，区分首帧、可交互、目录到达、媒体完成、首次请求和缓存请求。文件行数与单次 health 延迟都不能独立证明性能根因。

### 预览与开发工具

当前用户评审入口由本地开发说明维护，优先复用正确的服务和端口。不得用另一端口或 file:// 页面替换用户正在看的预览而不说明。

`dev:shell` 的画布路由可加 `?layoutTune=1`；`Ctrl + Shift + L` 切换布局调节器，临时参数仅保存在该标签页 sessionStorage。“复制参数”后将评审通过的值落实到正式 CSS / 几何规则；临时调节不写 CanvasDocument 或撤销栈。该工具只由 Vite serve 注入，不能进入生产构建。

## 4. 并行协作、集成与发布

- 多个独立任务使用各自 worktree；同一切片连续调整复用原目录与分支。独立研究、实现或验证可交给子代理，分配不重叠文件与职责，由主代理集成并验收；小改动不拆成多个代理。
- 开始或集成前盘点所有相关脏文件、提交与来源。其它任务未提交的工作不能覆盖、切分支或当成已经集成；重复改动先比较实际 diff。
- `main` 是已验证集成基线，新切片从最新基线建立 `codex/<任务>` 分支。遵守远端主线保护，经 PR 与必需检查集成，不直接绕过保护。
- squash merge 后，原功能分支仍可能显示旧提交未合并，但内容已进入主线。不要按“领先多少提交”重复整条合入；核对 PR、merge base、文件树及实际补丁。连续任务先同步主线，新任务从新基线开始；只移植仍未集成的改动，不强推共享分支消除历史。
- 本地提交、推送、PR 合并、构建、部署、提升主域与业务数据迁移分别核验。发布时记录源提交、实际目标与产物；候选验证后提升同一部署，不为重复文案重建。
- 推送 / 发布按用户已授权范围进行；本地功能完成不默认扩大为数据复制、seed 或公网发布。现有授权不反复索取，发现发布与数据目标不匹配先纠正。
- 报告只写已验证结果及实际限制。实现、检查、CI、部署与等待分开描述，不能把整轮耗时统称“同步”。

## 5. 清理与文档维护

| 对象 | 处理规则 |
| --- | --- |
| 未使用代码 / CSS | 查导入、HTML 与构建入口、动态拼接、事件绑定、桥接、初始化副作用及测试；确认不可达再删除。替代实现接入时移除旧路径 |
| 历史兼容 / migrations / fixture | 先明确支持范围和数据依赖；旧 migration checksum、fixture 指纹、已保存文档读取器不因“旧”而删除 |
| 重复文档 / 历史评估 | 唯一有效结论迁入对应规范，删除冗余正文与失效链接；历史通过 Git / PR 查，不再复制一份大归档 |
| 工作区 / 凭据 / 素材 / 产物 | 代码合入不等于可删除目录。先查脏文件、忽略数据、真实路径与运行进程；用户数据、凭据和保留源单独核对，不随代码清理 |
| 暂未实现页面 / 方案 | 只写扩展规划；跨模块架构取舍写 ADR，不把占位页面当成已实现 |
| 当前交接 | 只留最新基线、进行中范围、阻塞、下一入口与验证链接；替换旧状态，不追加流水账 |

文档职责固定：README 导航，AGENTS 启动约束，本工作流讲方法，设计规范讲视觉交互，工程护栏讲不变量，产品规范讲已实现，扩展规划讲未实现，local-development 讲运行与数据，vercel-supabase-preview 讲发布，ADR 讲决策。独立功能开发简版只在确有外部交接需要时保留，并链接权威规范。

完成时检查：改动可运行，旧路径已移除，相关检查通过，文档无失效引用，产品变化已更新对应章节，差异中没有凭据 / 数据 / 无关格式化。仍存债务如实说明，不为“规范化”一轮改写整个应用。
