# Reelay 前端原型交接说明

## 1. 当前状态

当前项目是纯静态高保真原型：

- 无后端。
- 无真实账号。
- 无真实模型 API。
- 无项目持久化。
- 无构建工具链。
- 无自动化测试框架。

当前目录已经初始化为 Git 仓库，默认分支为 `main`，基线提交为 `0cf1483`。其他 Agent 应从 `main` 创建独立分支，不要直接在基线上并行修改。

```powershell
git switch main
git switch -c feature/<task-name>
```

## 2. 文件职责

| 文件 | 职责 |
| --- | --- |
| `index.html` | 应用骨架与固定面板 |
| `styles.css` | 主题、画布、节点、Agent 和浮层样式 |
| `app.js` | 当前所有交互状态与画布逻辑 |
| `data/model-catalog.js` | 模型目录、展示元数据与参数能力表 |
| `docs/current-product-spec.md` | 已实现产品行为 |
| `docs/product-expansion-plan.md` | 未实现页面规划 |
| `docs/model-catalog-notes.md` | 模型命名和来源说明 |

## 3. 运行方式

```powershell
python -m http.server 5174 --bind 127.0.0.1
```

访问 `http://127.0.0.1:5174/`。

## 4. 关键产品约束

- “生成节点”是产品描述，不是节点永久显示名称。
- 双击空白创建节点，并沿用上一次节点模式。
- 生成节点未生成时不显示媒体名和媒体编辑工具栏。
- 本地素材节点不显示提示词面板。
- 选择模型后才改变图片 / 视频 / 音频节点类型。
- 图片、视频、音频模型处于同一连续列表。
- 多选节点、组框和组内节点有不同删除语义。
- 积分只在当前页面生命周期内计算，刷新重置为 `3000 / 0`。
- 主题和媒体工具栏偏好保存在 `localStorage`。
- 本地媒体使用对象 URL，刷新后不可恢复。

## 5. 当前数据边界

### 页面内状态

`app.js` 中的 `state` 保存：

- 画布位移和缩放。
- 节点与组。
- 选择状态。
- 项目名。
- Agent 会话。
- 测试积分。
- 分层资产库（项目素材、画布文件、个人、官方公用库、组织空间）。
- 当前主题和面板状态。

### 独立目录

模型数据已移到 `data/model-catalog.js`。新增模型时：

1. 使用稳定、唯一的 `id`。
2. 指定 `type`：`image`、`video` 或 `audio`。
3. 保留正式产品名，不把订阅层级写进模型名。
4. 描述保持一行，说明最有差异的能力。
5. 为 `capabilities` 补齐真实画幅、分辨率/画质、时长和数量。
6. 参数存在组合约束时使用能力映射，不在参数面板中硬编码供应商特例。

## 6. 已知工程风险

- `app.js` 和 `styles.css` 仍是大型单文件。
- 画布状态与 DOM 渲染紧耦合。
- 每次 `render()` 会重建节点 DOM，媒体播放和输入焦点需要特别保护。
- 撤销只覆盖部分删除行为，不是通用命令历史。
- 模型能力表仍是前端静态快照，尚未由供应商或后端能力服务实时同步。
- 资产和会话没有持久化。
- 外部示例媒体依赖网络可用性。

## 7. 推荐分支拆分

不要让多个 Agent 同时大范围修改 `app.js` 和 `styles.css`。

建议先做一个基础重构分支：

### `foundation/app-shell`

- 建立路由。
- 建立工作台应用壳。
- 提取主题、对话框、通知和菜单组件。
- 定义共享数据类型。

合并后再并行：

### `feature/project-home`

- 只负责项目首页与项目卡片。
- 不修改画布内部节点逻辑。

### `feature/asset-center`

- 负责资产列表、筛选、详情检查器。
- 复用 `Asset` 数据对象。

### `feature/generation-jobs`

- 负责任务列表、状态、重试和积分记录。
- 不直接操作画布 DOM。

### `refactor/canvas-modules`

- 把画布、节点、组、音频播放器和工具栏拆成模块。
- 保持现有交互不变。

### `feature/model-service`

- 将现有能力 schema 接入后端模型服务。
- 负责供应商状态、参数组合、地区可用性和计费映射。

## 8. 合并边界

- 新页面优先新增目录，不在 `app.js` 里继续堆页面代码。
- 修改共享 schema 时单独提交，先合并 schema，再合并页面。
- 模型目录修改集中在 `data/model-catalog.js`。
- 画布行为修改必须同步 `current-product-spec.md`。
- 未实现规划不要写成已完成功能。

## 9. 每个分支的最低验证

- `node --check app.js`
- 模型数据文件语法检查。
- CSS 大括号数量一致。
- 浅色和深色模式各检查一次。
- 1280×720 与窄屏检查。
- 控制台无错误。
- 功能区滚轮不带动画布。
- 页面刷新后积分重置。
- 未填写提示词时生成按钮不可用。
