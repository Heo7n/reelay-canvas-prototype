# Reelay 前端原型交接说明

## 1. 当前状态

当前项目是纯静态高保真原型：

- 无后端。
- 无真实账号。
- 无真实模型 API。
- 无项目持久化。
- 无构建工具链。
- 无自动化测试框架。

当前目录已经初始化为 Git 仓库，默认分支为 `main`，基线提交为 `0cf1483`。其他 Agent 应从 `main` 创建独立分支，不要直接在基线上并行修改。

```powershell
git switch main
git switch -c feature/<task-name>
```

## 2. 文件职责

| 文件 | 职责 |

| `index.html` | 应用骨架与固定面板 |
| `styles.css` | 主题、画布、节点、Agent 和浮层样式 |

## 3. 运行方式

```powershell
python -m http.server 5174 --bind 127.0.0.1
```

访问 `http://127.0.0.1:5174/`。

## 4. 关键产品约束

- “生成节点”是产品描述，不是节点永久显示名称。
- 双击空白创建节点，并沿用上一次节点模式。
- 生成节点未生成时不显示媒体名和媒体编辑工具栏。
- 本地素材节点不显示提示词面板。
- 选择模型后才改变图片 / 视频节点类型。
- 图片、视频模型处于同一连续列表；音频只作为上传素材，不提供生成模型。
- 多选节点、组框和组内节点有不同删除语义。
- 积分只在当前页面生命周期内计算，刷新重置为 `3000 / 0`。
- 分享、个人积分与 Agent 入口位于右上角同一操作组；积分显示在头像左侧，hover 头像预展开个人菜单，点击积分徽标才在菜单内显示积分详情。Agent 收起入口固定在个人入口右侧，不再支持拖动。Agent 展开或调宽时，右上操作组必须同步避让。
- 媒体编辑工具条和生成节点输入区使用屏幕可读性补偿，修改画布缩放时需要同时验证两者。
- 左上角统一使用 `Logo + 项目名 + 画布名` 的项目导航；资产库展开时隐藏画布上的顶部导航，只保留资产库面板内的同一套导航，避免双 Logo。
- 左下角资产库入口独立保留，画布工具顺序固定为 `小地图 → 适应视图 → 画布比例`；适应视图不是简单全量 fit-all，而是选中优先、未选中时全量可读优先、远距离离散时聚焦主内容簇；画布比例是 20% 到 200% 的行内滑条，不再使用百分比菜单，也不显示额外图标。快捷键入口位于右上角个人菜单的“帮助”二级小层级；hover 到帮助时只显示“快捷键 / 使用教程”，hover 到“快捷键”才展开快捷键说明。外观菜单项右侧是浅色、深色、跟随系统三个行内图标按钮，点击后滑块与左侧图标同步切换。
- 画布菜单已经支持当前页面生命周期内的添加、切换、复制、重命名和删除画布；不要把它描述为真实持久化多画布。
- 资产库默认展示当前项目的 `画布/资产` 两层；只有点击书本图标才进入个人、组织、官方公用库这些全局资产空间，进入全局后书本按钮变为返回项目资产库。
- 资产库可从右边缘拖拽调宽；卡片网格和画布树列表必须随宽度自适应。
- 全局资产库的个人空间、组织空间、官方空间位于顶部同一分段区域，不再使用左侧竖向空间栏。
- 资产库的画布列表是树状结构：组作为父级，组内节点缩进显示；点击任意组或节点会定位主画布。
- 项目资产列表使用卡片网格，并按角色、场景、道具、素材四类筛选；项目资产页不显示搜索入口。
- 全局资产库使用空间说明和文件夹视图，文件夹内默认预览显示，并可切换为列表显示；全局库暂不做角色/场景/道具/素材分类筛选，也不显示上传素材按钮。
- 主题和媒体工具栏偏好保存在 `localStorage`。
- 本地媒体使用对象 URL，刷新后不可恢复。

## 5. 当前数据边界

### 页面内状态

`app.js` 中的 `state` 保存：

- 画布位移和缩放。
- 节点与组。
- 选择状态。
- 项目名、画布列表和当前画布。
- Agent 会话。
- 测试积分。
- 分层资产库（当前项目内的画布/资产侧栏 + 书本图标进入个人、组织、官方全局资产库）以及画布元素树的折叠状态。
- 当前主题和面板状态。

### 独立目录

模型数据已移到 `data/model-catalog.js`。新增模型时：

1. 使用稳定、唯一的 `id`。
2. 指定 `type`：`image` 或 `video`。
3. 保留正式产品名，不把订阅层级写进模型名。
4. 描述保持一行，说明最有差异的能力。
5. 为 `capabilities` 补齐真实画幅、分辨率/画质、时长和数量。
6. 参数存在组合约束时使用能力映射，不在参数面板中硬编码供应商特例。

## 6. 已知工程风险

- `app.js` 和 `styles.css` 仍是大型单文件。
- 画布状态与 DOM 渲染紧耦合。
- `render()` 已改为基于节点/组签名的 DOM 复用，位置与选择变化不会全量重建；节点自身结构变化仍会替换该节点，后续模块化时应继续拆成局部更新器。
- `state` 仍是可变全局对象，写操作尚未集中到 store/action 边界，是多人协作前最需要处理的结构风险。
- 撤销已覆盖删除、移动、参数修改和重命名，但复制、建组、布局和生成任务仍未纳入完整命令历史。
- 模型能力表仍是前端静态快照，尚未由供应商或后端能力服务实时同步。
- 资产和会话没有持久化。
- 外部示例媒体依赖网络可用性。

## 7. 推荐分支拆分

不要让多个 Agent 同时大范围修改 `app.js` 和 `styles.css`。

建议先做一个基础重构分支：

### `foundation/app-shell`

- 建立路由。
- 建立工作台应用壳。
- 提取主题、对话框、通知和菜单组件。
- 定义共享数据类型。

合并后再并行：

### `feature/project-home`

- 只负责项目首页与项目卡片。
- 不修改画布内部节点逻辑。

### `feature/asset-center`

- 负责资产列表、筛选、详情检查器。
- 复用 `Asset` 数据对象。

### `feature/generation-jobs`

- 负责任务列表、状态、重试和积分记录。
- 不直接操作画布 DOM。

### `refactor/canvas-modules`

- 把画布、节点、组、音频播放器和工具栏拆成模块。
- 建立单一状态入口和显式 action，禁止业务函数直接散落修改全局状态。
- 将当前签名复用渲染器拆成节点级局部更新器，并为媒体播放和输入焦点补回归测试。
- 把现有撤销记录升级为可扩展的 command history。
- 保持现有交互不变。

### `feature/model-service`

- 将现有能力 schema 接入后端模型服务。
- 负责供应商状态、参数组合、地区可用性和计费映射。

## 8. 合并边界

- 新页面优先新增目录，不在 `app.js` 里继续堆页面代码。
- 修改共享 schema 时单独提交，先合并 schema，再合并页面。
- 模型目录修改集中在 `data/model-catalog.js`。
- 画布行为修改必须同步 `current-product-spec.md`。
- 未实现规划不要写成已完成功能。

## 9. 每个分支的最低验证

- `node --check app.js`
- 模型数据文件语法检查。
- CSS 大括号数量一致。
- 浅色和深色模式各检查一次。
- 1280×720 与窄屏检查。
- 控制台无错误。
- 功能区滚轮不带动画布。
- 页面刷新后积分重置。
- 未填写提示词时生成按钮不可用。
