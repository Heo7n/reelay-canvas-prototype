# Reelay 设计规范

本文约束新增界面和后续调整的共同视觉、交互与验收方式。具体功能行为以 [当前产品规范](current-product-spec.md) 为准，代码与检查流程见 [开发工作流](development-workflow.md)。参考图提供结构和体验方向；实现需结合产品已有密度、状态及真实内容校正，不照搬配色或把草图边框当成最终样式。

## 1. 现有来源与使用边界

基础字体已由 React 与画布共用同一来源；画布及其宿主加载 / 错误区共用画布语义色，公共键盘焦点共用一个浅深主题色。其余颜色、字号及组件仍按各表面维护，没有完整组件展示页。修改前先复用下列变量与组件，不新增一套同义值。

| 场景 | 当前实现来源 | 优先复用 |
| --- | --- | --- |
| React 与画布基础字体 | `styles/typography.css` | `--font-family-ui`，通过各自样式入口接入 |
| 画布表面与宿主过渡、公共焦点 | `styles/color-tokens.css` | `--color-canvas-*`、`--ui-focus-ring`；工作台材质不套用画布色 |
| 登录 / 账号面板关闭按钮 | `src/shared/ui/DialogCloseButton.tsx` | 36px 命中区、20px Lucide X、必填可访问名称；页面只负责位置与表面色 |
| 画布、节点、Agent 基础 | `styles/app.css` | `--surface`、`--text`、`--node-font-*`、`--agent-panel-*`、`--canvas-popover-*` |
| 画布边缘工具与面板 | `styles/canvas-chrome.css` | `--canvas-edge-*`、`--canvas-chrome-*` |
| 生成记录、引用与优化 | `styles/canvas-generation-*.css`、`styles/canvas-prompt-*.css` | 先消费基础变量，再使用功能内语义别名 |
| React 应用壳与工作台 | `src/app/app-shell.css`、`src/pages/home/WorkspacePages.module.css`、`src/shared/ui/` | 字体继承、`--workspace-*`、已有共享组件 |
| 模型品牌与通用图标 | `data/model-catalog.js`、`lucide-react`、`assets/icons/` | 模型目录的本地品牌资源及现有 Lucide 图标 |

工作台和画布允许不同表面材质；相同语义的正文、控件和状态需要可追溯的共同准则。公共 token 的后续提取应同时接入消费者并删除被替代定义，不新增无人使用的“统一层”，不借局部修改全仓改色。

## 2. 字体、颜色与留白

- 正文、输入和按钮继承所在应用的字体。React 宿主与画布共用 `styles/typography.css` 的 `--font-family-ui`：`Inter, "PingFang SC", "Microsoft YaHei", sans-serif`；画布空状态不另设字体。字体依赖设备已有安装，未额外下载字体文件。TaskId 等等宽内容和既有信息图形的专用字体保留；不在单个按钮中再引入正文字体。字号、字重、行高仍按各功能语义维护，后续字体调整须同时比较宿主与画布的中文、英文和数字。
- 默认阅读正文 `14px / 400`，控件 `13px / 400–500`，标签 `12px / 400`，弱辅助信息 `11px / 400`；这与现有节点层级相符。正文行高以 `1.5–1.7` 为起点，长文阅读可放宽；标题按层级使用 `16–24px / 500–600`。已有功能明确尺寸继续服从产品规范，例如模型菜单 `14px / 500`，不能因选中切换而推动排版。
- 不用缩小关键字或压扁文字解决拥挤；主操作、模型名称和任务详情优先保持可读，次要摘要按既有规则收敛。费用、时长等对齐数字可用 `tabular-nums`；不要把普通文字换成等宽字体。
- 颜色先表达语义：背景、表面、浮层、正文、次要文字、边界、强调、危险；用现有 CSS 变量或功能内语义别名，不在事件函数和模板中硬编码颜色。浅深主题分别定义，不用整块透明度同时降低文字与表面可读性。
- 主操作沿用中性高对比；轻强调只用于选中、可操作提示或明确状态。危险色留给删除、失败等语义，不用红色表示“有新结果”。状态还必须有文字、图标或形状区别，不能只靠颜色。
- 新增正常正文的对比度目标至少 `4.5:1`，必要控件边界和焦点标识至少 `3:1`；使用实际背景核对。浅色字和透明材质不能只凭观感判为合格，也不宣称既有界面已完成全量无障碍审计。
- 已接入共用焦点色的控件为登录 / 账号关闭按钮、账户分栏、工作台账户与帮助入口、项目删除操作和画布宿主重试 / 返回按钮；2px 实线替换原来的低透明度轮廓。焦点色在本轮核对的浅深表面上最低为 4.55:1；其它控件仍需随改动检查，不能据此宣称全站焦点已统一。
- 新布局优先从 `4 / 8 / 12 / 16 / 24 / 32px` 间距选择；既有紧凑控件的 `6 / 10px` 等值可保留。先对齐内容边缘、文字基线及图标中心，再做有证据的光学校正，不用随机 margin 抵消错误布局。组内间距应小于组间间距，避免为短内容预留固定空行。

## 3. 控件、图标与状态

- 同一操作层的按钮保持一致高度、圆角、图标尺度和行高。画布已有紧凑操作高 `32px`、工具栏按钮 `36px` / 圆角 `8px`；工作台主要导航命中区高 `44px`。按所在层复用，不把不同密度场景强制改成同一尺寸。新图标操作的命中区至少 `24 × 24px`，主要高频操作优先 `32px` 以上。
- 输入使用一层明确表面与边界，label、placeholder、帮助和错误各有职责；字符计数不得遮挡文本。焦点反馈不能导致尺寸跳动，错误不清空已填内容，输入法组合不误提交。
- 通用图标优先选已安装的 `lucide-react`。legacy 画布使用同源本地 SVG / 已提取的 Lucide 路径子集并保留许可证；新增子集记录来源版本，不加载完整图标包或外部 CDN。品牌图标和积分资产继续使用产品专用资源，不强制改成 Lucide。
- 通用线性图标优先 `16 / 20px`，相同控件组统一 stroke、viewBox、端点和视觉重量；继承 `currentColor`，不拿 emoji、Unicode 字符或临时拼线替代成熟图标。纯图标按钮有可访问名称，装饰图标对辅助技术隐藏。
- 实现时列出该控件适用的默认、hover、pressed、selected / expanded、focus-visible、disabled、loading、error 状态。hover 不替代焦点；disabled 不伪装为可点击；loading 只限制冲突操作，不能无理由锁住整个输入区。
- 列表和任务明确区分加载中、空数据、筛选无结果、失败、成功与取消。toast 只承载短反馈，持久错误与需要用户处理的状态留在相关区域；不重复常识性提示或把模拟实现细节塞进产品界面。

## 4. 浮层、预览与动效

- 菜单、说明、可交互预览、全屏媒体和模态对话框各自承担明确职责；不要为了复用外观而混淆关闭、焦点与滚动语义。可操作内容不能只有 hover 入口，需支持点击或键盘。
- 浮层复用现有定位能力（如 `canvas-popover-placement.js`、对应功能 controller），按真实锚点和可用视口避让，允许内部滚动。需要越过画布裁切的菜单优先沿用原生顶层机制；不要不断增大 `z-index` 掩盖层叠上下文问题。模态中的从属菜单必须留在相应顶层与焦点范围。
- 模态限制焦点范围，Escape 与关闭按钮语义一致，关闭后归还入口焦点。破坏性确认沿用当前确认框，明确对象、影响及是否可撤销；原生弹窗并不代替保存/取消的状态设计。
- 关闭按钮共用视觉与原生 `type="button"`，不持有弹窗开关状态、异步任务或焦点圈。登录仍由原生 dialog 管理模态，账号 / 删除面板仍用原有容器；不因共享关闭按钮就认定整套模态实现已统一。登录与账号使用 `captureFocusReturn` 捕获实际入口，包含同源 iframe 内的控件；账号面板的焦点与滚动清理只随打开 / 关闭发生，分栏切换不触发。工作台回到持续可见的账户入口，画布回到头像入口，已移除的入口不强行聚焦。
- 媒体预览按比例完整展示或按明确的缩略图规则裁切，不拉伸；视频、音频按需挂载播放器。切素材、关面板或销毁后停止播放并释放资源。预览层标题、关闭按钮与留白按功能需要提供，不无条件套统一大标题框。
- 轻交互可从现有 `120–180ms` 淡入 / 小幅位移起步；连续变形保持空间关系，避免生硬切高度。视觉动效与内容出现协调，不能等入口动画结束才开始展示内容。hover 意图延迟与动画时长分开处理，已有滚动抑制和固定阅读规则见产品规范。
- 优先动画 `opacity` / `transform`；必要的尺寸动画保持正文、滚动和底部操作可用。响应 `prefers-reduced-motion`，减少非必要位移及循环效果，状态完成不依赖动画结束事件。

## 5. 主题、容器与验收

- 同次改动同时检查浅色与深色，特别是浮层不透字、禁用态可辨、焦点可见。画布与 React 宿主沿用现有主题桥同步，不新增第二个主题存储或用重载画布实现换肤。
- 当前产品目标是桌面。窗口宽度约束全局导航与页面版心；可拉伸侧栏、节点输入和浮层内部按真实容器宽度布局，优先使用现有 container query / 几何状态，不用窗口断点代替容器变化。
- 不为满足“一行”隐藏主操作或缩小到不可读。先控制首选 / 最小 / 最大宽度、允许文本区伸缩、收敛次要内容；只有产品明确允许时才换行或折叠。短窗口中固定操作保持可访问，长内容在所属区域滚动，不带动画布；具体滚轮规则见工程护栏。
- 本轮涉及的界面至少核验常规宽度、支持的最窄容器、短窗口、长名称 / 多行正文、空与多素材，以及适用的加载和失败状态；不要求每次局部修改遍历全站。检查鼠标、Tab / Escape、焦点返回、主题与控制台；涉及画布缩放时另查屏幕尺寸和世界尺寸的关系。
- 对照已确认参考时使用相同窗口、侧栏宽度与内容，核对布局、字体、行高、间距、图标和状态。将结论写入本次交付，发现不一致直接修对应规则；只通过语法 / 单元测试不能宣称视觉验收通过。

## 6. 渐进收敛

优先整理经常重复修改的按钮、输入区、Popover、确认框及媒体引用。下次修改这些表面时先找已有实现，必要时把同一语义提取为共享 token / 组件并让相关消费者同步接入；完整替换旧路径后再扩展。基础字体已接入共享来源；尚未统一的颜色别名、字号变量和浮层尺度应留在可执行任务中，不在本规范宣称完成；不以重写 legacy canvas 或引入大型组件平台作为正常功能开发前置条件。

## 7. 下一轮讨论与落定

下表是需要讨论的产品方向，不代表已批量改造。开发分层、根因修复、状态归属、数据隔离、键盘可操作与按影响测试等底线继续按现有工作流执行，不重新询问是否需要。

| 决定什么 | 建议方向 | 范围与当前边界 |
| --- | --- | --- |
| 整体视觉与配色 | 让创作媒体成为视觉重点，界面以中性色为底；选中 / 引用轻强调，危险色只表达危险 | 暂保留工作台与画布的轻微材质差异；品牌色、成功 / 警告 / 危险配对尚未全站收敛 |
| 信息密度与字重 | 工具操作紧凑、内容阅读舒展两档；普通控件优先 400–500，强调按层级使用 | 不增加密度设置；部分旧账户控件仍有 680–760 字重，需在实际界面集中对照后迁移 |
| 图标语言 | 继续 Lucide，按操作语义固定图标、尺寸与描边；品牌标识单独维护 | 已有本地子集逐步补来源记录，不随页面引入另一套图标库 |
| 删除、撤销与恢复 | 按对象和后果决定确认方式；能可靠撤销的低风险操作优先撤销，不能恢复的操作明确确认 | 项目、素材、生成记录分别定规则；软删除不等于已有可用回收站 |

落定时用真实的按钮、输入、菜单、预览和生成记录做少量对照，确认后将值写进前面的正式规则和消费者；删除对应待定项，不另建一份重复设计文档。还需随功能定下空 / 错 / 忙碌状态、键盘与焦点顺序、长文与窄容器、动效和媒体控制、可撤销边界、数据备份与失败可诊断性，而不仅是静态配色和字号。
