# 提示词优化开发说明

优化先产生可审阅建议，用户明确填入才修改 Prompt。当前约 1.8 秒处理为本地模拟，不接真实 AI、不扣积分、不自动发送。

## 用户看到的规则

- 同一节点或同一轮对话草稿已有成功结果，再点优化先打开上次“优化前（原文）/ 优化后”，改文字、模型或参考不会丢失结果。
- 填入保留结果；当前输入仍等于刚填入的建议时，主按钮显示禁用的“已填入”。编辑建议后可以再次填入。
- 用户另改输入、模型或参考后，主按钮为“优化当前内容”，明确处理当前输入，不用旧建议覆盖新草稿。
- 重新优化时，已填入且未另改的内容仍以最初原文为源，避免反复扩写。手改同源建议后重新优化须确认丢弃这些修改。
- 重试中或失败时保留上次成功的原文与建议；新成功才同时替换。引用保留稳定素材身份，不转成普通文字。
- 对话框只有成功受理发送才进入下一轮草稿；空输入、失效引用等发送失败保持原轮次。旧优化完成和旧撤销不能写入下一轮。

## 模型优化配置

头部下拉仅列当前模型的平台默认与自定义方案，不再挤占对照正文。平台默认提供说明“平台默认会随当前生成模型自动切换对应的优化规则。”，实际平台指令不展示、不进入自定义表单。

自定义方案通过行内编辑入口或底部“+ 自定义优化配置”进入独立小面板：填写名称、目标模型、指令（最多 2000 字符）；新建为空，编辑已有方案时锁定模型。保存当前模型方案会选用，为其他模型新建仅保存而不切换模型或目标原选择。编辑使用原 ID 原子更新，取消或校验失败不改保存内容。

模型 ID 是唯一分组键，同模型不同生成模式、节点与对话草稿共用配置。配置区跟随当前输入模型，对照区仍可显示上次成功模型，两者不能混用。保存 / 切换配置仅影响下一次请求，旧结果与进行中请求保持其冻结指令。

平台规则来自模型目录的 `optimizationInstructions`，用于执行输入，不在界面展示；当前仍是前端本地模拟，不代表浏览器源码不可读取。偏好使用本机 v2 存储；旧全局指令或默认项草稿迁移成可见“自定义草稿”，选择平台默认始终使用真实平台规则，不再有隐藏覆盖。尚未实现账号云端同步。

## 状态与代码职责

| 部分 | 职责 |
| --- | --- |
| `src/application/prompt-optimization-service.js` | 冻结请求、模拟处理、保留成功配对、失败与取消 |
| `src/application/prompt-optimization-preferences.js` | 按模型管理默认、自定义保存 / 选择和本机迁移（公开 API 为 get / select / save） |
| `src/legacy-canvas/canvas-prompt-optimization-controller.js` | 节点 / 草稿轮次所有权、已填入快照、配置、通知、明确应用与安全撤销 |
| `src/legacy-canvas/canvas-prompt-optimization-view.js` | 对照面板、可编辑建议、引用预览与动作状态 |
| `app.js` | 提供当前目标、参考与模型快照，执行 Prompt 写入；节点复用画布撤销 / 保存，会话只改编辑器草稿 |

`getDraftOwner(conversation)` 在本轮返回同一个不透明对象。仅发送成功受理后调用 `advanceDraft(conversation)`。切换 / 重命名会话、关闭面板、修改输入与填入不会换轮次。实际对象身份和作用域共同校验，不能只凭字符串 ID 复用结果。

“已填入”比较当前输入 / 模型 / 参考与上次写入快照，并同时检查建议是否变化。不能仅以“现在的输入不等于最初原文”判断陈旧。撤销除了核对文本仍匹配，还必须核对实际目标和草稿轮次；恢复上次写入时也恢复其来源记录。

## 验证范围

定向检查包括 service、controller、view，以及真实节点 / Agent 集成：已有结果重开、显式再优化、已填入 / 编辑后填入、非递归重试、失败保留配对、引用身份、发送成功 / 失败的轮次边界、迟到回调和撤销，以及当前模型配置、不同模式共用、方案原子保存 / 跨模型保存、存储迁移和并发请求的冻结指令。代码里程碑继续按 `development-workflow.md` 执行完整检查。
